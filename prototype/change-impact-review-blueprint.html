P2.1 · CHANGE IMPACT REVIEW

这次改动，会影响谁？

DataOps 不扫 SQL。它消费 ChangeSet 和 code scan findings，把变更映射到 package、资产、下游和发布风险，让 Agent 和用户看到“改这里会碰到哪里”。

边界SQL 语法、DDL/DML/Rollback、破坏性字段由 code scan / CI 判定；DataOps 只补数据侧影响和发布上下文。

Code scan / CI 负责

  • SQL parser 和语法
  • DDL / DML / Rollback 配套
  • 删表、删字段、改类型、改分区
  • 破坏性 SQL 的阻断判断

DataOps 负责

消费 ChangeSet 和 scan findings，映射到 package、资产、lineage 下游、owner 和发布风险。没有扫描结果就说“未提供”，不假装通过。

ACCEPTANCE

这一版必须成立的事

  1. 无 ChangeSet 时只显示空状态
  2. 3 个文件正确映射到 package
  3. 资产缺失时有明确 gap
  4. 关键下游有 warning
  5. scan blocking 只继承不重判
  6. 没有 scan 结果不显示通过
  7. DataOps 不解析 SQL AST
  8. 所有输入来自当前 workspace

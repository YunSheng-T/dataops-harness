阶段产物 / 知识

Artifacts / WorkItem 阶段拥有

每个产物只有一个 owner 阶段；下游引用，不复制。落到文件系统，可 diff、可审、可交接。

requirementdesignprofile / solutiontech-plan / speccode / schedulecicd / postmortem

Skills 知识层，不属于插件

只做判断、流程、模板、评审清单；不碰数据，不直接写平台。

workitem-protocolsql-reviewmodel-reviewlineage-impactpipeline-debugschedule-yamldata-profilingcicd-gate
一句话：阶段只回答“现在做什么、交什么”，组件只回答“谁提供能力、谁访问外部”。公共能力放共享层，阶段卡片保持薄；不要为每个阶段建一个插件。
单向数据流client → tool → provider → 外部；UI 不直连外部，SKILL 不碰数据。
一产物一 owner每个设计产物只归一个阶段；下游引用，不复制，避免两套真相。
一系统一 providerDataMap、调度、CICD 各一个适配；不按阶段 fork 适配层。
阶段不拥有能力table / lineage / evidence / profile 是共享事实，阶段只声明何时需要。
先契约后卡片新增能力顺序：契约 → provider → tool → 校验 → 卡片 → 阶段映射 → 技能。
写操作留在外部部署、建表、触发任务仍走现有审批/发布系统；工作台只到草稿。

05 · Tool Registry

工具名描述动作，不描述产物

scope + action + object；共享工具不带阶段名，阶段专属工具不带 shared。schema 见 tool-registry.js。
compile 边界：Agent + schedule-yaml SKILL 负责产 schedule-spec；CICD 的 dataops_cicd_compile 只负责调用内部 CLI dataops compile <artifact>，回传 YAML/diagnostics。Tool 不回调 Agent，也不替 Agent 做方案选择。

01 · Goals

要做什么，明确不做什么

v1 的完成标准是“陌生机器上一条命令装完、可升级、可卸载”；不是做一个新桌面产品。
Goals · v1 必须成立

可发放的安装单元 核心

  • 一个包：@dataops/dsh-dataops-bundle@0.1.0 组合 4 个精确版本的 DataOps 包。
  • 一条官方路径：从 shipped web 模板初始化 profile，再用 dsh plugin --profile dataops add 安装。
  • 双入口：CLI / Web 与 DSH Desktop 共用同一个 DSH_HOME（本机实测 ~/.dsh）。
  • 双运行时：0.2.1-rc.2（Desktop 2.0.18 自带）与 0.2.1-rc.3（仓库 pin）都能装。
  • 可撤销：receipt + 升级 / 回滚 / 卸载；用户配置与 workitems 保留。
成功口径：干净机器 → 安装 → dump-config / 启动 / Desktop 三模式通过 → 卸载后用户数据仍在。
Non-goals · v1 不做

边界之外，先不伸手 明确排除

  • 不改 upstream：不 fork、不改 @deepseek-ai/*，能力只通过 patch / 插件叠加。
  • 不做桌面 App：不自带 Electron，不改 DSH Desktop；品牌只约束产品名与 Logo。
  • 不做 DSH 自动更新：runtime 升级仍由 DSH / Desktop 负责，安装器不代管。
  • 不接真实 provider：v1 保持 mock 默认，只留 tokenRef / baseUrlEnv 配置缝。
  • 不做公共 market：内部 npm registry + 离线 tarball，公开市场后置。
任何一条越界，都要单独立项和 ADR，不夹带进发布模型。

04 · User Journey

安装是一条可验的流水线

六步，每步有明确通过条件；失败分支在下方，不靠“再试一次”。
Step 01 · preflight

环境预检

用户 / 安装器

读 dsh --version、pnpm、DSH_HOME；确认安装会执行代码并写入 profile。

dsh --version
pnpm --version
通过：版本在 engines 范围
Step 02 · seed

初始化 web profile

安装器

从 shipped web 模板创建 dataops profile，保证 @deepseek-ai/dsh-web-app 存在。

dsh --profile dataops --from-default-profile web --dump-config
通过：bundles 含 base + web-app
Step 03 · install

官方安装

dsh CLI + pnpm

交给官方 plugin 命令解析 bundle 与精确依赖，pnpm 生成 lock，不手写 manifest、不做绝对 symlink。

dsh plugin --profile dataops add \
  @dataops/dsh-dataops-bundle@0.1.0
通过：依赖树完整、lock 落盘
Step 04 · verify

配置与启动验证

安装器 / CI

--dump-config 检查 4 个包行、品牌禁用、默认 preset；再跑 headless smoke。

dsh --profile dataops \
  --dump-config
通过：行齐、preset 默认、0 报错
Step 05 · skills

技能（默认安装）

独立 artifact

默认装到 $DSH_HOME/skills；可选 --workspace 到项目 .agents/skills。先做重名 preflight，冲突默认停止；只带筛选后的 DataOps 工作流技能，不装 upstream 的 dsh-* 开发技能。

dataops-install --skills-only (M2)
→ $DSH_HOME/skills
通过：无重名、可回滚
Step 06 · launch

启动 / 切换

用户

CLI 直接起；Desktop 重启 App 后选 dataops profile。receipt 由安装器写入，不靠首次启动补记。

dsh --profile dataops
Desktop: 重启 → 切换
通过：会话可建、品牌正确
engines 不匹配安装或启动时直接拒绝；提示当前版本与支持范围。用 compatibility.json 豁免不在方案内。
缺 web-app新 profile 只有 base 时 Desktop 报错；seed 步骤先校验 bundles 含 web-app，缺则停止。
用户 patch 被改安装器只备份现有 cordis.patch.yml，不改正文；需要改默认值时只提示 diff，不自动合并。
registry 不可达切离线 tarball + sha256；校验失败或版本不符就停止，不进半安装状态。
技能重名preflight 列出冲突技能；中止或由用户选择跳过，不覆盖已有技能目录。
旧 dataops profile 共存M4 验收前旧 dataops profile 与脚本保留；验收后立即退役。不把旧 symlink profile 当作发布产物。
目标形态：dataops-install / dataops-doctor / dataops-uninstall 是 M2 才实现的安装器入口；当前仓库仍用 dev 脚本，本页不把它们写成已可用。官方底层命令 dsh plugin add 现在可用。
失败可诊断：错误必须带“对象 + 当前值 + 期望值 + 下一步”，例如 “profile dataops 缺 web-app，请重新按 web 模板初始化”。
05 · Two Entries

CLI / Web 与 Desktop，同一套 profile

同一个 DSH_HOME，同一个 profile；区别只在宿主是否注入 desktop shell。
Entry A · 原生

CLI / Web：dsh --profile dataops

headless 验证与日常开发的主入口；不依赖桌面壳，适合 CI 与远程机器。

  • 直接加载 dataops profile 的独立组合；session / workspace 仍由 DSH 统一管理。
  • --dump-config 是安装后的第一道可审证据。
  • 不继承 desktop profile 的任何插件；能力只来自 base + web-app + bundle。
  • Web GUI 端口由 dsh 分配，安装器不另起服务。
Entry B · Desktop

DSH Desktop：重启并切换 profile

Desktop 2.0.18 自带 rc.2 runtime；读同一个 DSH_HOME，列出自定义 web profile。

  • 启动时自动注入 desktop shell；不需要改 Desktop 代码。
  • 先重启 App，再在 profile 列表选择 dataops。
  • 不继承 desktop profile 的 market / bridge 等插件；因为组合是显式的。
  • 已知限制：宿主页面 / 窗口标题可能仍是 DeepSeek Harness 或 DSH Desktop，插件运行时改不了；品牌只覆盖侧栏与空会话。
Desktop Mode 01

compatibility · 兼容

最小面：App 能启动、profile 被识别、4 个包加载、品牌与 preset 正确；默认推荐此模式。

必测 · 默认推荐
Desktop Mode 02

extended · 扩展

在兼容面之外验证自定义 web profile 的列出 / 切换、会话创建与工具调用。

必测
Desktop Mode 03

advanced · 高级

验证 overlay 配置、技能 root、离线安装与回滚；具体模式定义以 Desktop 文档为准。

必测
不共享 desktop profile 的生态位：market、bridge 与 desktop 专属插件不进入 dataops profile。用户若需要，应显式在 overlay 中追加，而不是由安装器默认继承。
06 · Compatibility

rc.2 / rc.3 双运行时，硬门禁

engines 是唯一口径；不靠 compatibility.json 或“应该能跑”做豁免。

Gate A · 版本兼容

能不能装

安装前预检 runtime 版本；启动时 engines 再校验一次。失败即停，不进入半安装。

证据：--dump-config 在两版 runtime 各跑一次
Gate B · 发布完整性

产物可不可信

构建可复现、依赖锁定；发布附 sha256，registry 有 ACL；签名/attestation 后置。本机验收走离线 tarball，registry/ACL 在 M3 内网补测。

证据：本机 tarball 校验记录 + 内网 registry 发布日志
Gate C · 安装验收

装完对不对

dump-config 检查行与默认值；Desktop 三模式；升级 / 回滚 / 卸载演练各一次。

证据：receipt + 三模式验收记录
不用兼容性豁免：compatibility.json 之类“绕过 engines”的开关不进入本方案。版本不兼容就升级 runtime 或发新的 bundle 版本，两者必须显式对应。
07 · Lifecycle

装、升、回、卸，都有收据

安装 receipt 是本地唯一事实源；升级和回滚都只是“add 另一个版本”。
01 · install

安装

dataops-install 封装 seed → add → verify 并写 receipt；底层仍是官方命令。

dataops-install (M2 目标)
02 · upgrade

升级

add 新版本；重跑 verify；旧版本信息留在 receipt 历史。

... add bundle@0.1.1
03 · rollback

回滚

add 旧版本；离线时用保留的 tarball；不需要手改 lock。

... add bundle@0.1.0
04 · uninstall

卸载

脚本删除 profile 与 receipt；按清单清理技能；workitems 保留。

dataops-uninstall
Receipt · schema 1

$DSH_HOME/dataops/install.json schema 1

{ "schema": 1, "bundle": "@dataops/dsh-dataops-bundle", "version": "0.1.0", "dshVersion": "0.2.1-rc.3", "profile": "dataops", "installedAt": "2026-10-31T00:00:00Z", "artifacts": ["profile", "bundle", "skills"], "skillRoot": "$DSH_HOME/skills", "sha256": "<bundle digest, optional>" }

receipt 只记录事实，不替代 lockfile；版本真相仍在 profile 的依赖与 lock。

Retention · 保留与清理

卸载不删用户资产

  • 保留：workitems、workspace 文件、session、用户已有技能、用户 overlay 备份。
  • 清理：dataops profile 目录、bundle 依赖、receipt、由本 artifact 安装的技能条目。
  • 不碰：desktop profile、home patch、DSH runtime、其他 profile。
  • 重启：Desktop 卸载 / 回滚后仍需重启再切换，避免旧进程持锁。
dataops-uninstall 必须打印“保留了什么、删除了什么”；dataops-doctor 输出版本、profile、dump-config、技能与日志路径（均为 M2 目标）。
升级与回滚同构：两者都是官方 add 指定版本，安装后都跑同一套 verify；差别只在目标版本与 receipt 的 previous 记录。这样不需要第二套升级逻辑。
08 · Trust & Compliance

从构建到运行，证据不断链

安装即执行代码；每一跳都要有可核对的来源、校验或权限。
01 · build

可复现构建

源码 pin + lockfile；不 fork upstream；产物不含凭据与本地路径。

02 · checksum

校验与签名

tarball 附 sha256；签名/attestation 后置，等产品成熟和安全团队具备密钥/CI 流程后再补。

03 · registry ACL

谁能发布

内部 registry 按 @dataops scope 限权；读权限给内网安装者。

04 · consent

安装即代码执行

安装前明示将执行的代码、写入目录、技能 root；默认不静默写全局。

05 · runtime

启动复检

engines 再校验；provider 凭据只走 credentials / env，不落 bundle。

Known

09 · Invariants

八条不做，避免过度改造

发行模型只改“怎么装”，不改“装的是什么能力”。
1 · 不 fork upstream不改 deepseek-harness/ 与 @deepseek-ai/*；补丁需 ADR 与移除条件。
2 · 不写 desktop profile不改 DSH Desktop 代码；现有 desktop profile 零写入。
3 · 不打包 runtime不携带 DSH runtime、node_modules、session、workitems、真实凭据。
4 · 品牌只换名字 / Logo不重写 Web UI、不改官方主题与 @deepseek-ai/* 包。
5 · 工具契约不变工具名、payload、卡片契约与 workitem 格式保持兼容。
6 · engines 强校验版本不匹配即拒绝；不用 compatibility.json 豁免。
7 · 用户 patch 不被覆盖安装器只补 bundle 层；已有 overlay 只备份、不改正文。
8 · v1 只支持独立 profile现有 desktop profile 安装列为未来 / 高级选项，默认不做。
为什么独立 profile：品牌替换、默认 preset、工具集全会侵入用户现有工作环境。v1 用独立 profile 把风险隔离在 dataops 内，用户随时可切回。

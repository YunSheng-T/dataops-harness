2026-10-31

四个本地包，
收成一个安装单元。

相对当前“开发机本地安装”，变的不是 Stage 0–5，也不是工具契约；变的是发布单元、安装路径、配置与技能的生命周期。这是一版只看增量的对照页。

Before · 4 个 private 包 After · 1 个 bundle + receipt 换官方安装器 0 处 Desktop 改动
一句话改动只改发行层

从“4 个私有包 + 手写 profile + 绝对 symlink + 全局技能”变成“1 个自包含安装入口 + 官方 pnpm profile + $DSH_HOME/skills + 可撤销 receipt”。

01 · Change Summary

四个变化，其余保持

阶段语义、卡片、工具契约、workitems 全部不动；只重做“怎么装、怎么发”。
Change 01 · Unit

安装单元：4 个包 → 1 个入口

新增 dataops-bundle 作为唯一安装入口；运行时仍依赖 4 个包，由 patch 组合 tools / brand / client / preset。依赖精确版本，声明 engines。

4 个独立包 1 个安装入口
Change 02 · Install

安装：手写 + symlink → 官方 pnpm

先用 shipped web 模板 seed，再让 dsh plugin add 解析 bundle 与 4 个依赖；不再手写 manifest 或绝对链接。

file: · 绝对 symlink registry · pnpm lock
Change 03 · Release

发布：手工拷贝 → 两条流水线

构建校验后发内部 registry；同时出离线 tarball + sha256。安装 receipt 记录版本、dshVersion 与 sha256（source 可选）。

无发布渠道 registry / tarball
Change 04 · Lifecycle

配置 / 技能：全局侵入 → 专用边界

配置进 bundle + 用户 overlay；技能迁出 ~/.agents/skills，默认装到 $DSH_HOME/skills 并做重名 preflight。

全局技能软链 artifact + DSH_HOME root
净变化：新增 1 个安装单元与 1 份安装 receipt；替换安装脚本与包来源；配置与技能从 profile / 全局迁出；Desktop、upstream、工具契约与 workitems 保持不变。M4 验收前旧安装路径仍可用；验收通过后立即退役。

04 · Migration

M0 冻结 → M4 验收，通过后立即退役

对应全量蓝图的 P0 / P1 / P2；每步都有退出条件，不跨步合入。
M0 · freeze

冻结现状

记录 4 包版本、symlink 安装、全局技能与 Desktop 行为；保留可复现基线。

不写 runtime、不改 Desktop。
退出：现状可复现，基线测试通过。
M1 · bundle

bundle 与 patch 生成

新增 packages/dataops-bundle；迁入 4 行、品牌禁用、默认 preset；补 engines / license / notices。

对照 dump-config：行与默认值等价。
退出：只装 bundle 也能得到同一棵树。
M2 · installer

官方安装器

seed web 模板 → dsh plugin add → verify → receipt；dataops-install 等为 M2 目标。overlay 只备份、不改正文。

干净机器一条命令安装；幂等。
退出：安装 / 重装 / 失败回滚可诊断。
M3 · release

发布流水线 / registry

build → verify → pack → sha256 → 内部 registry；同步出离线 tarball。本机只验 tarball；registry/ACL 在 M3 内网补测。

本机 tarball 安装通过；内网 registry / ACL 补测。
退出：内网可从 registry 或 tarball 安装。
M4 · desktop

Desktop / 离线验证

rc.2 + rc.3；Desktop 2.0.18 三模式；升级 / 回滚 / 卸载各演练一次。

0 启动报错；Desktop 三模式与升级 / 回滚 / 卸载演练通过。
退出：兼容矩阵与操作演练全绿。
M5 · docs

文档与旧路径退役

发行说明、安装 / 升级 / 回滚文档；M4 验收通过后立即退役旧脚本与全局技能软链。

迁移说明覆盖保留 / 清理项。
退出：旧 dev 路径已退役，release 文档只保留新路径。
兼容期
M0–M4 期间旧 dataops profile 与安装脚本保持可用；M4 验收通过后立即退役，不保留长期双路径。退役前必须发一次性迁移通知。
迁移原则：先让新路径可回滚，再谈替换。M1 完成前不动安装器；M2 完成前不发 registry；M4 验收通过后立即退役旧路径。
05 · Invariants

不变的边界，防止过度改造

这六条与全量蓝图一致；实现时若触碰，先改设计和 ADR。
Invariant 01
upstream 只读不 fork、不改 deepseek-harness/ 与 @deepseek-ai/*；领域能力只走 patch / 插件叠加。
Invariant 02
desktop profile 零写入安装器不碰 desktop profile；v1 只支持独立 dataops profile。
Invariant 03
工具 / 数据契约不变工具名、payload、卡片契约与 workitem 格式保持兼容；发行改造不改能力语义。
Invariant 04
品牌只换名字 / Logo不重写 Web UI，不动主题与官方包；宿主标题限制如实披露。
Invariant 05
不打包 runtime / 凭据bundle 不含 DSH runtime、node_modules、session、workitems 与真实 token。
Invariant 06
engines 硬门禁版本不匹配在安装 / 启动时拒绝；不引入 compatibility.json 豁免。
唯一真正变化的：安装边界从“本机 checkout”变成“可发布 artifact”。Stage 0–5、工具、卡片、审批与 workitems 全部保持原样。

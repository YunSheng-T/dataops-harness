## 3. 真实 rc.4 运行时装配 smoke

环境：`/Applications/DSH NEXT.app`（2.0.21-next，内核 rc.4）的 Electron 以 `ELECTRON_RUN_AS_NODE=1` 运行 npm 包 `@deepseek-ai/dsh@0.2.1-rc.4` 的 CLI，profile 为 `~/.dsh/profiles/dataops`（已由安装脚本接入 dataops-dev 符号链接）。

> 注：裸 `node` 跑 rc.4 CLI 完整启动会在 app-boot 报 Electron 指纹错误（`node-addon-require-builtin unsupported`），这是运行时对 Electron 的硬要求，与本插件无关；`--dump-config` 不走该路径。

### 3.1 配置组装

```
DSH_HOME=~/.dsh ELECTRON_RUN_AS_NODE=1 "<DSH NEXT>/Contents/MacOS/DSH NEXT" \
  ~/.npm/_npx/.../dsh/lib/bin.js --profile dataops --dump-config
```

输出末尾包含，且全量组合无报错：

```yaml
- id: dataops-dev
  name: '@dataops/dsh-dataops-dev'
```

### 3.2 完整启动（正向）

```
... --profile dataops --port 0 --no-open   # 运行 25s 后终止
```

输出仅一行（web 服务就绪），**零错误、零告警**：

```
dsh web: http://127.0.0.1:53131/?token=…
```

HTTP 探测：带 token 根路径 → 303，无 token → 401，服务行为正常。

### 3.3 破坏对照（负向，证明观测通道有效）

向 `src/host/index.js` 末尾临时注入 `throw new Error("sabotage-proof…")` 后启动，运行时明确报告：

```
dataops-dev (@dataops/dsh-dataops-dev): failed to import: Error: sabotage-proof: dataops-dev apply reached
    at file:///…/packages/dataops-dev/src/host/index.js:18:7
```

即：运行时会真实加载我们的入口文件，且插件失败一定会被点名报告。因此 3.2 的干净启动可认定为 dataops-dev 加载并 apply 成功的有效证据。对照完成后已恢复文件，回归测试 19/19 PASS，复跑启动依然干净。

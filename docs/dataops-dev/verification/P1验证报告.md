### 跨工作区保存反馈回归（2026-11-02）

用户在 `internal-code-repo` 的「工作区内修改」会话中发现：文件能打开，但保存一直回到「确认未落盘」；同一实例的 `dataops-harness` 文件可以保存。根因是 UI 保存未向 `ctx.fs.writeText` 传递当前 Session 的 sandboxPolicy，导致沙箱使用进程默认工作区；确定性的 `FS_SANDBOX_DENIED` 又未被映射，误入 save-unknown 对账。

修复提交 `d58cdd0`：live Session 通过 `sandboxPolicy.resolve({ session })` 取得当前 mode/cwd，冷 Session 保留部署默认 mode 并恢复持久化 cwd；写入携带该 policy，sandbox 拒绝映射为确定性的 `dev/read-only`。没有放宽用户权限。

`sandbox.test.mjs` 三项回归覆盖 live 工作区、冷工作区、权限拒绝且磁盘不变。重启 3088 后，用户在原 `internal-code-repo` 会话中确认「可以保存了」，真实浏览器复验通过。

## 4. P0 结论修正

P0 报告曾将「`$mount` 未导致 UI 异常」作为 Remote 装配证据，但当时的挂载失败只进入 console，空视图并不能证明 Remote 可用。P1 首次真实调用暴露了 descriptor codec 和动态服务注入问题，本轮已按 rc.4 源码修复，并由冷 Session 的真实打开→编辑→保存闭环验证。旧结论不应继续单独引用为 Remote 可用证据。

## 5. 已知限制与偏差

1. 外部变化通过 4 秒轮询和 window focus 对账，不是原生 `changes` 事件；不声称实时协同。
2. `FsInfo` 没有 mode，只读采用保存失败后的反应式降级。本轮用目录不可写真实触发；不能只用文件位 `0474` 推断结果，因为 fs-local 原子 rename 仍可能成功。
3. `deliverables.file.actions` owner 没有 `fileAddress`，P1 入口使用原生预览的 `absolutePath`；预览交接采用插件内 pending handoff + 公开 `uiConversation.activate`。
4. UI-01 本轮实测原生文件预览入口；完整 `openView` 的 Chat/Diff 深链未分别做浏览器端到端验收。
5. Remote descriptor 仍为手写，但已满足 rc.4 的 strict codec 与 cancellation 合同；未切换到 typert 生成工具链。
6. P1 没有文件树、Inspector、Parser 或结构化旧值。UI-04 只验收编辑器与冲突视图；UI-05 的结构化 stale、Provider failure 留到 P3，不伪造本阶段场景。
7. 正式安装/发布路径仍未在本轮扩展；验收使用既有 dev profile 与符号链接。

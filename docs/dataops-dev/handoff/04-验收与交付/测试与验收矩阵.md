# 测试与验收矩阵

本地 Agent 必须把下列场景映射到真实测试文件和执行命令。不能只写测试名称，必须运行并保留结果。集成测试优先使用真实 ctx.fs、真实 policy chain 和本地 DSH Host；内存 fake 只用于纯模型单测。

## A. 打开、保存与冲突

| ID | 场景 | 必须证明 |
|---|---|---|
| DOC-01 | read 期间文件变化 | stat 前后不一致会重读，永不返回 version A + content B |
| DOC-02 | 正常保存 | replaceIfVersion 成功，新 baseVersion/savedDigest/receipt 正确 |
| DOC-03 | 保存前 Agent/外部写入 | stale-version，local 保留，current 不丢，进入 conflict |
| DOC-04 | 写成功但响应丢失 | save-unknown → reconcile saved，不重复写，不伪造 receipt |
| DOC-05 | 请求未执行且版本未变 | reconcile not-saved，只有用户显式重试 |
| DOC-06 | 保存期间继续输入 | 只保存快照 S，新输入 T 仍 dirty |
| DOC-07 | clean 外部更新 | 安全刷新，保留视图位置，显示 Diff |
| DOC-08 | dirty 外部更新 | 不覆盖 local，base/local/current 齐全 |
| DOC-09 | hot-exit 磁盘未变/已变 | 分别恢复 dirty/conflict，均不自动保存 |
| DOC-10 | 大文件、非法 UTF-8、非普通文件 | 只读降级或拒绝，无截断保存、无替换字符 |
| DOC-11 | 幂等键重用 | 同 key 同内容返回原结果；同 key 不同内容稳定报错 |
| DOC-12 | 文件删除或权限变只读 | local 可导出，不继续写，不伪造成功 |

## B. Agent 与文件策略

| ID | 场景 | 必须证明 |
|---|---|---|
| AGT-01 | Agent clean 直改 | dirty guard 后仍进入原生 observation policy |
| AGT-02 | Agent 未读取就写 | 仍得到原生 FS_NOT_OBSERVED，不被 UI bridge 放行 |
| AGT-03 | Agent dirty 直改 | dev/document-dirty，磁盘 digest 不变，可转 Proposal |
| AGT-04 | 其他 actor 写 | 无 UI bridge 特权，继续原生 policy |
| AGT-05 | preset 顺序错误 | 启动合同测试失败或安全失败，不静默关闭防护 |
| AGT-06 | Proposal digest 过期 | 禁止应用，不按旧 range 修改 |
| AGT-07 | 默认 dirty 隐私 | Agent 只能读 saved，draft 不进 prompt/tool output |
| AGT-08 | 显式草稿共享 | 只读固定 snapshot，scope/digest/授权可审计 |
| AGT-09 | presence 过期后回线 | external/conflict 对账，不声称实时无损协同 |

## C. 结构化与 Diagnostics

| ID | 场景 | 必须证明 |
|---|---|---|
| STR-01 | 含注释、未知字段、多父依赖 YAML 改标量 | 只改目标标量，其余源码保留，生成 draft 不保存 |
| STR-02 | 前文行数变化后恢复节点选择 | 按 entityRef 恢复，不用数组下标 |
| STR-03 | 拖动节点 | YAML 不变，布局不进 Artifact |
| STR-04 | YAML 语法错误 | 文本可编辑，结构化不可用，不用空 DAG 冒充成功 |
| DIA-01 | 分析期间连续输入 | 旧 request 丢弃，旧诊断 stale，不覆盖新结果 |
| DIA-02 | projection/diagnostics/sourceMap 异步返回 | 只按 analysisId 原子替换，不混版 |
| DIA-03 | draft 与 saved 结果 | subjectKind/digest 明确，draft 不进 Evidence |
| DIA-04 | Provider 失败与合法空结果 | 两种状态不同，可保留旧成功值并标 stale |
| DIA-05 | UI Slot 尝试注入诊断 | 合同无通道，只有 Host Registry 结果可成为事实 |

## 首版完成定义

- 所有 P0/P1 安全与并发场景通过；P2～P4 若声明完成，对应场景也必须通过。
- 类型检查、lint、单元测试、集成测试和本地 DSH 启动验证均有真实命令与结果。
- 主界面、dirty、save-unknown、conflict、read-only、Provider failure 和窄容器至少各检查一次。
- 没有为通过测试而删除安全断言、跳过大文件/冲突场景或启用生产 mock。
- 未验证项目明确列入限制，不能用“代码已写”代替“已验证”。

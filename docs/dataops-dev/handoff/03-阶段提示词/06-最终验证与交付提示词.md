# 最终验证与交付提示词

```text
现在对 dataops-dev 做最终验证，不新增大功能。阅读交接包全部验收材料和各阶段报告，使用 04-验收与交付/最终验证报告模板.md、偏差记录模板.md。

任务：
1. 检查 git diff 和变更文件，确认没有无关格式化、用户改动覆盖、上游核心 fork、真实凭据、生产地址或 mock fallback。
2. 按本地 DSH 真实命令运行依赖一致性检查、类型检查、lint、单元测试、集成测试和构建。不要修改 build script 绕过错误。
3. 重新运行 P0 文件策略安全测试、P1 并发/保存未知测试、P2 Agent dirty/隐私测试，防止后续阶段回归。
4. 运行结构化、Diagnostics、Artifact、Slots 测试；检查测试不是只验证静态类型或 mock UI。
5. 在本地真实 DSH 启动环境验证：原生 Chat/Trajectory 仍在；开发 view、Files 深链、同一文件单 tab、保存、Agent clean/dirty、冲突、结构化、诊断、Artifact 门禁和窄容器。
6. 检查主界面与冲突界面，无 fixed 全屏、无关键按钮遮挡、无空白页式降级、无静态演示数据冒充真实解析。
7. 审计日志和错误：无完整 draft、Secret、真实环境参数；保存回执/内容对账/冲突选择可区分。
8. 更新最终验证报告：实际 commit、变更文件、命令与结果、界面证据、验收矩阵逐项状态、偏差、已知限制、运行方法。
9. 明确区分“已实现且已验证”“已实现未验证”“未实现”。不要写生产已部署或已发布。

不 commit、不 push、不 merge、不部署。若关键安全/并发测试失败，最终状态必须是未通过，并优先修复上游原因，不删除测试或降低合同。
```

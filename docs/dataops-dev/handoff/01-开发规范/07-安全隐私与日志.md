# 安全、隐私与日志

## 必须实现的安全控制

| 风险 | 控制 |
|---|---|
| 路径与权限绕过 | 认证 principal 绑定 Session；Host 重新解析 fileAddress；lstat 和 sandboxPolicy；focus 不是权限凭证 |
| Agent 文件策略绕过 | Agent/其他 actor 必须 next()；不伪造 observation；不 actor=undefined；P0 组合合同测试 |
| 用户草稿泄露 | 默认不发 draft；共享需显式、单次、固定 digest；hot-exit 可禁用、TTL、Session 隔离 |
| Secret/环境值泄露 | 诊断、Projection、Artifact 上下文只含占位符键名和安全字段；真实值不进 prompt、卡片、日志、fixture |
| 任意外部调用 | actionId 来自 Registry；URL/连接只来自配置或环境；生产禁止静默 mock fallback |
| UI 权限错觉 | allowedActions 仅展示；Host 每次重算；Agent/UI 同命令路径；Agent 不自签 |
| 不可信 Slot | 只读 props、schema callback、Error Boundary、贡献者版本；不暴露 ctx、可写 Store 或诊断事实通道 |
| 并发数据丢失 | FsVersion、idempotency、save-unknown reconcile、三方 conflict；失败保留本地草稿 |

## 日志审计

可以记录：documentId、安全化文件标识、base/target/saved digest、actionId、结果码、providerVersion、耗时和 requestId。

默认不记录：完整源码、draft text、真实环境参数、Secret、连接凭据和可还原敏感数据的错误堆栈。

保存审计必须区分：

- Host 正常保存回执。
- 按内容对账确认。
- 用户冲突选择。
- Agent Proposal 的 offered/applied/dismissed/stale。

这些事件不能混成一种“成功”，Proposal 也不能代替 Approval、保存或验证。

## 测试数据

单元测试和集成测试使用显式、最小、脱敏 fixture。可以包含 `$$DB_EXEC$$` 等占位符键名，但不能包含真实值。不得把生产数据复制到测试快照，也不得让测试 fake 在生产装配不可用时自动启用。

## 生产与环境

生产默认只读。写操作需要明确受控环境、权限和 audit。企业调度、CICD、发布、回滚和审批仍由原系统拥有。本地开发只验证插件和本地 DSH，不执行部署。

# UI 交互与状态

## 1. 原生入口

使用 `conversation.view` 注册 `dataops-dev`，与 Chat、Trajectory 并列。原生文件卡片、预览、Diff、诊断和结构化节点通过 `openView('dataops-dev', focus)` 进入，完成后调用 `completeViewRequest()`。

DevLocationV1 包含 v、fileAddress、可选 line/column/entityRef/source，编码为版本化受限 opaque focus。focus 有长度和 schema 上限，不是权限凭证，Host 打开仍重新校验。

定位顺序：fileAddress → 同 digest SourceMap 中的 entityRef → line/column → 文档顶部。非法或过期 focus 不得跳转到其他路径。

同一 IDE Session 中规范化 fileAddress 相同则聚焦已有 tab，保留 dirty、撤销栈和视图状态，不创建第二个 buffer。

## 2. 文件树和 Diff

文件树优先复用通用 `sidebar.files.tree` Factory；不要误用与 Sidebar tab 生命周期耦合的 `sidebar.files.navigator`。原生文件预览和 deliverables file actions 只增加“在开发中打开”。

原生 Diff 是轮次快照，不等于当前磁盘内容。Diff 的动作只能打开当前文件或定位，不得直接覆盖编辑器。

## 3. 主界面

- 文件区：原生文件树、打开文件和状态标记。
- 文档工作区：Tabs、编辑器、源码/结构化切换、Diagnostics、冲突模式。
- 上下文区：Inspector、Artifact、Agent Proposal、外部状态。
- DSH 原生右侧栏继续独立可用，focus 只能在当前容器放大，不能 fixed 全屏。

标题栏必须显示路径、sync、savedDigest 和只读原因。Diagnostics 显示 subjectKind、digest、provider 和 active/stale。Artifact 在 dirty 时明确显示最后 saved 版本与未保存提示。

## 4. 响应式

| 宽度 | 布局 |
|---|---|
| ≥1440px | 文件区约 240px + 弹性文档区 + Inspector 约 320px，Diagnostics 底部 |
| 1100–1439px | 文件区可折叠，Inspector 可切换，文档区优先 |
| 760–1099px | 单主列，文件树和 Inspector 用容器内 drawer |
| <760px | 非主要开发形态，只保证阅读、定位和草稿不丢 |

## 5. 冲突界面

冲突是文档工作区模式，不是一次性错误弹窗。base/local/current 同时保留，显示各自 digest 和来源，暂停保存与自动刷新。

“采用 current”二次确认；“保留 local 为草稿”只改基线；“手工合并”生成 merge draft。三者都不允许隐式自动落盘。

## 6. 空态与降级

- 无文件：提示从 Files、Chat 文件卡片或 Agent Diff 打开，不显示静态演示源码。
- 无 Parser：文本 IDE 可用，结构化 tab 隐藏或 unavailable。
- projection stale：保留旧值并标旧 digest，不与新源码冒充同版。
- analysis failed：保留文本和 dirty，显示 Provider 错误与重试。
- 大文件/非 UTF-8：回退原生只读预览，不截断保存。
- Slot 崩溃：显示贡献者 ID 并降级该面板，编辑器继续工作。

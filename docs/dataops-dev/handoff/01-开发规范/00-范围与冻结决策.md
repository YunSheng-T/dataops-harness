# 范围与冻结决策

## 目标

在 DSH 原生 Session 中新增 `dataops-dev` 数据开发 IDE，使用户与 Agent 围绕同一份源码安全编辑、解析、诊断和调用产物动作。插件是核心，不建设独立 DataOps 应用外壳。

## 首版必须实现

1. `conversation.view = dataops-dev`，支持版本化 focus 深链和同文件单文档模型。
2. DevDocument 一致性打开、受防护保存、幂等、保存未知对账和只读降级。
3. clean/dirty 两种 Agent 协作模式、外部变化通知和 base/local/current 三方冲突。
4. task.yaml 结构化投影、SourceMap、白名单标量编辑。
5. Draft/Saved Diagnostics 生命周期及 subjectDigest 绑定。
6. savedArtifactRef、动作状态矩阵和统一 Host invokeAction。
7. 五类受限 Slots 与 Host Provider Registry。
8. 与上述能力对应的自动化测试和本地 DSH 实际验证。

## 首版明确不做

- 实时多人 CRDT、自动保存、跨设备草稿同步。
- 完整 Git 客户端、通用 LSP 平台、任意语言可视化设计器。
- 非 UTF-8 转码编辑、大文件截断后保存、format-on-save。
- 任意 DAG 拖边重写依赖、整份 YAML 对象 dump。
- 企业验证、Package、Deliverable、调度、部署和审批系统的替代实现。
- 为了让演示通过而加入生产 mock fallback。

## 八项冻结决策

| 编号 | 决策 |
|---|---|
| D1 | IDE 以 `conversation.view` 进入 DSH，原生 Chat、Files、Diff、Approval 和右侧栏保持。 |
| D2 | 首版手动保存、全量文本、UTF-8 普通文件、`replaceIfVersion(FsVersion)`。 |
| D3 | clean 允许 Agent 原生直改；dirty 只允许 EditProposal；冲突三方处理。 |
| D4 | UI actor 使用独立受限 bridge；Agent/其他 actor 必须继续原生 policy。 |
| D5 | 结构化视图是只读投影，白名单标量通过 TextEdit 生成新 draft。 |
| D6 | Draft diagnostics 与 saved Evidence 分层，结果按 subjectDigest 原子替换。 |
| D7 | Artifact 推进只接受 savedDigest，Host 每次重算 allowedActions。 |
| D8 | 其他插件只通过五类 Slots、Remote、Resource 和 Host Registry 扩展。 |

## 实现优先级

可靠性优先于视觉效果。P0 的文件策略组合未被真实代码证明前，不允许把精力投入 DAG、主题美化或更多面板。

编辑器内核建议 CodeMirror 6，但允许使用 DSH 仓库已有且能满足相同合同的编辑器。内核变化不得改变 DevDocument、digest、冲突或 Slots 合同。

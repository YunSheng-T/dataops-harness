# 技能模板

复制下面的骨架到 `.agents/skills/<kebab-case>/SKILL.md`，目录名与 `name` 必须一致。

```markdown
---
name: <kebab-case>
description: <何时用 + 产出什么，一句话；这是唯一常驻上下文的文字>
---

# <中文标题>

## 何时用
- <具体触发场景，3–5 条>
- 不适用：<排除场景，指向其他技能>

## 先取事实（缺什么就问，不要猜）
1. <必须知道的输入>
2. …

## 流程
1. <第一步：先做什么、看什么>
2. …

## 判定口径
- **阻断**：<什么情况必须停>
- **需修改**：<什么情况要返工>
- **建议**：<什么情况只是优化>

## 输出格式
<用代码块给出固定结构，让模型每次产出一致>

## 反例
- <最常见的错误做法，3–5 条>

## 工具（P1 后可用）
- `<tool.name>`：<拿什么>；不可用时<降级路径>
```

## 写完自检

- [ ] `description` 是一句话，且包含「何时用」；没有把它写成正文摘要。
- [ ] 正文 < 8000 字符；更长的材料拆到 `references/`。
- [ ] 流程是**可执行步骤**，不是原则罗列。
- [ ] 有明确的输出格式（模型产出一致，人好复核）。
- [ ] 有反例，且反例是真实会犯的错。
- [ ] 工具未实现时写了降级路径。
- [ ] 没有硬编码表名、账号、内网地址。
- [ ] 用三个真实任务验证过：会被触发、产出可用。

## 什么时候该拆成两个技能

- 触发场景互斥（评审 vs 排障），且步骤没有重叠；
- 一个技能的正文超过 8000 字符，且后半部分只在少数场景用到；
- 两个技能需要不同的工具集或不同的权限级别。

## 什么时候不该新建技能

- 只是多了一条检查项 → 加到现有技能的「判定口径」里；
- 只是某张表的特殊规则 → 写进 `AGENTS.md` 或部署配置；
- 只是希望模型「更懂业务」→ 先补 `AGENTS.md` 的领域上下文，技能只放流程。
